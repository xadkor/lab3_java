### Текст задачи
**2.5 Маршрут.**
Данная задача предполагает разработку новой сущности на основе той, что была получена в задаче 1.4.8 (Город). Сущность Город может быть доработана по своему усмотрению для более удобного использования.

Основная идея задачи в разработке такой сущности, которая будет представлять собой маршрут между двумя городами. Данный маршрут в любой момент времени можно получить как массив для дальнейшего использования. Сущность Маршрут имеет следующие характеристики:
- Имеет Город начала и Город конца пути.
- Инициализация Маршрута может быть выполнена только если указана точка начала и конца пути. Если указано null значение — то ошибка.
- Точку начала и конца можно изменить в любой момент времени, но они всегда должны существовать.
- Может вернуть массив Городов, представляющий собой маршрут из начала в конец. Массив содержит все Города (в порядке очереди), через которые надо пройти, чтобы попасть из Города начала в Город конца, причем и начало и конец также содержатся в этом массиве. Алгоритм формирования пути в данном случае не существенен, можно выбрать вариант со случайным путем, путем проходящим через наименьшее число городов, или самым дешевым путем. Если путь найти невозможно — возвращается пустой массив.
- Маршрут может быть приведен к строке, которая будет возвращать название всех городов маршрута в порядке очередности.
- Создание объекта и изменение точек начала и конца выполняется за константное время O(1).

Воспользуйтесь картой городов из задачи 1.3.3 и выведите маршрут из Города F в Город D

### Алгоритм решения
1. Создан класс `Route` с двумя полями: `start` и `end` типа `City`.
2. Конструктор и методы `setStart`, `setEnd` проверяют значение: при `null` бросается `IllegalArgumentException`. Поэтому начало и конец всегда существуют. Создание объекта и смена точек это простое присваивание, то есть O(1).
3. Метод `getRoute()` ищет путь с наименьшим числом городов поиском в ширину. Очередь `ArrayDeque` хранит города для обработки, `visited` помнит посещённые, а `previous` хранит для каждого города, из какого мы в него пришли.
4. Если конечный город не посещён, путь не найден, и возвращается пустой массив. Иначе путь восстанавливается от конца к началу по `previous`, разворачивается через `Collections.reverse` и возвращается массивом.
5. Для `visited` и `previous` используются `IdentityHashMap` и множество на её основе: города сравниваются по ссылке, а не через `equals` (который переопределён в задаче 6.5 и считает равными города с одинаковыми дорогами).
6. Метод `toString()` выводит названия городов маршрута через ` -> ` или сообщение «Маршрут не найден».
7. В `Main` строится карта городов A–F из прошлой лабораторной (рисунок 2) и выводится маршрут из F в D, например `F -> B -> A -> D`: дороги из E в D нет, она ведёт только из D в E.

### Алгоритм решения

5. В `Main` вводятся названия двух городов и стоимость. Дорога добавляется один раз из первого города, и на экране видно, что она появилась в обоих городах. После `removeRoad` она исчезает из обоих.

**8.4 Клонирование точки.**
Измените сущность Точка из 2.6.2. Переопределите метод клонирования, унаследованный от класса Object, таким образом, чтобы при его вызове возвращался новый объект Точки, значения полей которого будут копиями оригинальной Точки.

### Алгоритм решения
1. Класс `Point` реализует интерфейс `Cloneable`: без него `Object.clone()` бросает `CloneNotSupportedException`.
2. Метод `clone()` переопределён с типом возврата `Point` (ковариантный тип): он вызывает `super.clone()` и приводит результат к `Point`. Исключение `CloneNotSupportedException` перехватывается и превращается в `AssertionError`, потому что при реализованном `Cloneable` оно возникнуть не может.
3. `Object.clone()` создаёт новый объект того же класса и копирует значения всех полей. Поля `x` и `y` имеют тип `int`, поэтому поверхностного копирования достаточно.
4. В `Main` пользователь вводит координаты, создаётся точка и её клон. После изменения координаты оригинала выводятся оба объекта: копия осталась прежней. Проверка `original == copy` даёт `false`: это разные объекты.
